# 用户指南

## 第一次使用

1. 打开 Sotto，点击“选择文件夹”或把作品根目录拖进窗口。
2. 等待扫描完成，Sotto 会自动生成一份**整理方案**，不会立即改动文件。
3. 逐项检查：配对是否正确、文件名将变成什么、哪些字符会被删除、是否要转码、封面是否合适。
4. 点击“执行整理”。完成后可一键撤销。

## 四个核心动作

### 1. VTT/SRT/TXT 转 LRC

默认开启。对每个配对成功的字幕生成同名 `.lrc`。如果文件夹里已经有 LRC，会优先使用现有 LRC。

- 支持 `track.mp3.vtt` / `track.wav.vtt` 这种双扩展名：配对时会去掉媒体后缀，源字幕会被改名为 `track.vtt`。
- 支持“扩展名是 .txt、内容其实是 WebVTT/SRT/LRC”的歌词：设置里开启“识别并转换 TXT 歌词”后，会按内容判断；普通剧本、readme 不会误转。
- 纯文本歌词如果没有时间轴，无法自动生成同步 LRC，会保留原文件并提示。


- 老车机乱码：在“字幕”设置里把输出编码改成 **GB18030**；
- 新设备首选 **UTF-8**；部分播放器需要 **UTF-8 BOM**；
- 默认保留原 VTT/SRT，并在**它们自己所在的目录**内同步改名（例如作品/字幕/xxx.vtt 会变成 作品/字幕/03 xxx.vtt），不会把源字幕搬进音频目录；转换出的 LRC 则写到音频旁边。可在设置中改为转换后删源（进回收站）。

### 2. 文件名严格对齐

Sotto 以音频文件名为准，生成一个“安全主干名”，然后把音频、字幕、LRC 都改成同一个主干名。默认删除：

- 表情与符号：♡ ☆ ♪ 等；
- Windows 非法字符：`< > : " / \ | ? *`；
- 控制字符、零宽字符、私有区字符。

保留：中日韩文字、拉丁字母、数字、常见标点（可在设置里改允许列表）。任何删除都会在方案的“删除字符”里逐个展示。

注意：没有字幕的音频默认不改名；如需一并整理，在“命名规则”里打开“无字幕音频也重命名”。

### 3. 选择封面

展开文件夹后点击封面区域，从该文件夹及子文件夹的图片中选择一张。Sotto 会把它移动/重命名为：

- `cover.jpg`（默认，兼容性最好）
- 或 `folder.jpg` / `front.jpg` / `album.jpg` / `封面.jpg`

如果原图不是 JPEG，且 ffmpeg 可用，会转换成 JPEG；否则保留原格式并提示兼容性风险。已存在同名封面时默认不覆盖，可在设置里允许覆盖（会先备份以支持撤销）。

批量整理时，可以在「设置 › 封面」打开 **自动选择封面**：优先选 cover/folder/front/album/封面 等明确命名的图片；文件夹里只有一张图时也会自动选中；候选很多且命名不明确时会跳过，不会强行拿一张场景图当封面。手动选过的封面永远优先。


### 4. 音频转码（可选）

在“音频”设置里开启，选择 MP3 或 M4A，以及码率。方案中会显示每个文件的转码目标。原文件默认保留；开启“删除原文件”后会移入回收站。

WAV/FLAC 转 192kbps MP3 通常可节省 70%–85% 空间。ASMR 以人声为主，128–192kbps 一般足够；对音质敏感可选 256/320。

转码默认只处理“与字幕配对成功”的音频。没有字幕的音频需要在「设置 › 命名规则」里打开 **无字幕音频也纳入整理**，才会一起改名并转码。

## 批量模式（推荐工作流）

1. 先在「设置」里把命名规则、字幕、封面、音频转码调成你的常用预设；这些设置会持久化。
2. 把整个作品根目录（例如 `[ASMR]`）拖进窗口，或选择该根目录。
3. Sotto 会递归扫描所有子文件夹，自动配对音频/字幕（包括 .mp3.vtt 和 TXT 歌词），生成完整方案。
4. 在方案里可以搜索、筛选“有警告”，核对低置信度配对；不需要逐个文件夹点确认。
5. 点击一次“执行整理”，即按当前预设处理全部选中的项目；完成后可一键撤销。

说明：封面是唯一可能逐文件夹手动选择的项目；如果不想手动，开启“自动选择封面”。方案在执行前不会改动任何文件。

## 设置详解

- **外观**：三套主题、深浅模式、强调色、密度、圆角、字号、透明度、减少动效。
- **命名规则**：NFKC、表情清理、仅 ASCII、允许标点、额外删除/保留字符、长度上限、无字幕音频改名。
- **字幕**：输出编码、删除源字幕、元数据标签、多行合并、时间偏移、TXT 歌词识别。
- **封面**：自动选择封面、封面文件名、JPG 转换、覆盖已有封面。
- **音频**：转码开关、格式、码率、删除原文件、输入格式、ffmpeg 路径与检测。
- **工具**：版本、日志目录、项目主页。

## 常见问题

**Q：为什么我的播放器还是显示不了字幕？**
A：确认 LRC 与音频主干名完全一致；尝试 GB18030 或 UTF-8 BOM；部分设备只识别 `[mm:ss.xx]` 格式并忽略元数据标签。

**Q：改名后播放列表会失效吗？**
A：会。Sotto 会重命名音频文件本身，部分播放器以路径为索引，需要重新扫描曲库。建议先在小范围试运行。

**Q：转码会损失音质吗？**
A：有损转码不可逆。Sotto 默认保留原文件，确认满意后再手动删除；也可以在设置里开启“删除原文件（回收站）”。

**Q：撤销能恢复删除的文件吗？**
A：重命名、新建 LRC、封面覆盖都可以撤销；进入回收站的原文件需要从 Windows 回收站手动还原。包含删除操作的运行会标记为“不可完整撤销”。

**Q：会上传我的文件吗？**
A：不会。应用没有任何网络请求；ffmpeg 也是本地进程。

**Q：为什么只转码了一部分音频？**
A：转码默认只覆盖与字幕配对成功的音频。没有字幕的 BGM、音效等会保持原样；如需一起处理，在「设置 › 命名规则」打开“无字幕音频也纳入整理”。

**Q：中文、方括号、空格的路径能用吗？**
A：可以。Sotto 全部使用 Windows Unicode 路径 API；已经用包含 `[ 施法素材 ]`、中文和空格的真实 Steam 创意工坊目录做过扫描/配对/转字幕测试。转码调用 ffmpeg 时也使用参数数组，不做脆弱的字符串拼接。

**Q：会不会被 Windows Defender / 杀毒软件误报？**
A：可能，尤其未签名 exe 和自解压 portable。降低概率的方法：使用 CA 代码签名证书、优先分发 NSIS 安装包而非 portable、不要 UPX 压缩、向杀毒厂商提交样本。自签名只能让本机信任，不能替代 CA 证书。详见 [SIGNING.md](SIGNING.md)。

**Q：32 位 Windows 能用吗？**
A：提供 ia32 构建。转码需要对应架构的 ffmpeg；如果安装包未内置，可在设置中指定。
